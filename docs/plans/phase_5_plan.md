# Phase 5 Implementation Plan: Streaming Responses & Optimization

## Goal
To address the LLM response delays, we will implement Server-Sent Events (SSE) / Streaming across the entire stack. This will stream the response chunks to the UI as they are generated by Ollama, vastly improving the perceived loading time and creating a much better user experience.

## Proposed Changes

### 1. Python AI Service (FastAPI)
- **`rag_service.py`**: Update `generate_chat_response` to use `ollama.generate(..., stream=True)`. We will change the function to yield text chunks as a Python generator instead of waiting for the full response.
- **`routes.py`**: Update the `/chat` endpoint to return a `StreamingResponse` so it streams the generator's output directly to the Node.js API Gateway.

### 2. Node.js API Gateway (Express)
- **`chatController.ts`**: Update the `handleChat` endpoint to request a stream from the Python backend by passing `{ responseType: 'stream' }` to Axios.
- Set the appropriate HTTP headers for Server-Sent Events (SSE) (`Content-Type: text/event-stream`).
- Pipe the incoming Python stream directly to the outgoing Express response stream.

### 3. React Frontend
- **`ChatInterface.tsx`**: Replace the `axios.post` chat request with the native browser `fetch` API, as `fetch` handles streaming data much more elegantly.
- Implement a `ReadableStream` reader to parse the incoming chunks.
- Update the React message state iteratively so the text appears in the `MessageBubble` as if it's being typed out in real-time.
